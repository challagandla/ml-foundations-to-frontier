01 · Python I: Values, Variables & Control Flow

Every model in this course — from a fitted line to a transformer — is ultimately a short Python program. This module assumes you have never programmed before, and by the end you'll be able to read a program and predict, line by line, exactly what it will do. That skill — tracing — is the whole game.

Learning objectives

  • Trace a short Python program by hand, line by line
  • Use int/float/str/bool values and variables correctly
  • Steer a program with if/elif/else, while, and for loops

A program is a list of instructions

Python reads your file top to bottom and executes one statement at a time. At any moment, the state of the program is just two things: which line runs next, and what each variable currently holds. If you can track those two things, no program can surprise you.

The instructions operate on values, and every value has a type. Four types cover most beginner code:

The four core types

int — whole numbers: 42, -7, 0
float — decimal numbers: 3.14, -0.5, 2.0
str — text in quotes: "hello", 'ML'
bool — truth values: True, False

A variable is a name attached to a value with =: price = 120 means "make the name price refer to the value 120." Read = as "gets", never as mathematical equality — count = count + 1 is nonsense as an equation but perfectly normal code: compute the right side first, then attach the name to the result.

    Math deep dive What numbers really are inside Python
    

      
Python's int is exact and unbounded. Unlike most
      languages, 2 ** 1000 just works — Python grows the integer as needed,
      so integer arithmetic never overflows or rounds.

      
float is neither. Floats are IEEE-754 double-precision:
      64 bits holding a sign, an exponent, and 52 bits of fraction — a binary
      scientific notation. Numbers like 0.1 have no finite binary representation (for the
      same reason 1/3 has no finite decimal one), so Python stores the nearest representable
      value. That's why:

      
>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False

      
This isn't a Python bug — every language using IEEE-754 (all mainstream ones) does
      this. The practical rules: never compare floats with == (use
      abs(a - b) < 1e-9 or math.isclose), and expect ~15-16
      significant decimal digits of precision. This will matter again when gradient descent
      accumulates millions of tiny float additions in later modules.

    

  


  
Making decisions: if / elif / else

  
Programs get interesting when they branch. Python checks each condition
  top to bottom and runs the first block whose condition is
  True — then skips the rest, even if later conditions would also be true.
  Indentation isn't decoration in Python: the indented lines are the block.

Repetition: while and for

  
A while loop repeats its block as long as a condition stays true.
  A for loop repeats once per item in a sequence — and the
  beginner workhorse sequence is range():


  
total = 0
for n in range(1, 6):   # n takes the values 1, 2, 3, 4, 5
    total = total + n
print(total)             # 15


  
Two things trip everyone up at first: range(1, 6) excludes
  the stop value (it ends at 5, not 6), and range(5) starts at 0.
  Explore both below.

Worked example

  
Classify a number as positive/negative and even/odd — the classic first
  trace-by-hand exercise. Follow it on paper before checking below:

  
x = -8

if x >= 0:
    sign = "positive"
else:
    sign = "negative"

if x % 2 == 0:          # % is remainder: -8 % 2 is 0
    parity = "even"
else:
    parity = "odd"

print(x, "is", sign, "and", parity)

  
Trace: x gets -8. The first condition -8 >= 0 is
  False, so the else block runs and sign gets
  "negative". Then -8 % 2 is 0, so parity
  gets "even". Output: -8 is negative and even.


  

    
Common pitfalls

    
= vs == — one = assigns, two
    == compare. Writing if x = 5: is a syntax error; Python will
    refuse to run it.

    Two kinds of division — 7 / 2 is 3.5 (always a
    float); 7 // 2 is 3 (floor division).

    Indentation is syntax — mixing indent widths, or forgetting to indent
    after a :, is an IndentationError. Pick 4 spaces and never
    think about it again.
