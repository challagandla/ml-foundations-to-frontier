Part 1 · Package work into functions

Why functions exist

Suppose you must convert three temperatures from Celsius to Fahrenheit. Without functions you copy the formula three times:

Repetitive — one bug fix needed in three places

c1 = 20
f1 = c1 * 9 / 5 + 32

c2 = 30
f2 = c2 * 9 / 5 + 32

c3 = 100
f3 = c3 * 9 / 5 + 32

One definition, three uses

def to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

f1 = to_fahrenheit(20)
f2 = to_fahrenheit(30)
f3 = to_fahrenheit(100)

A function is a named block of code that performs one job, may accept inputs, and usually produces an output. You have already used functions: print(), len(), and int() are built-in functions. Now you will write your own.

1 · Name an idea

to_fahrenheit(20) states intent; 20 * 9 / 5 + 32 only states arithmetic.

2 · Fix bugs once

The formula lives in exactly one place, so a correction applies everywhere it is used.

3 · Test one piece at a time

You can check to_fahrenheit(100) == 212 on its own, without running a whole program.

The anatomy of a definition

def to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

def is the keyword that starts a function definition. Read it as “define”.

to_fahrenheit is the function's name. It follows the same rules as any variable name: letters, digits, and underscores; no digit first; snake_case by convention. Name functions after what they do.

(celsius) is the parameter list — the names this function will use for the values it receives. Empty parentheses () mean “no inputs”.

The colon : ends the header line and announces an indented block, exactly like if and for in Module 01.

The indented lines are the function body — the code that runs on each call.

return ends the call immediately and sends a value back to whoever called it.

Two separate moments: definition and call

Definition time. When Python reads def, it does not run the body. It only creates the function object and attaches the name to it.
Call time. When Python reads to_fahrenheit(20) — the name followed by parentheses — it jumps into the body with celsius set to 20, runs the body, and comes back with the returned value.

This is why nothing appears to happen when you run a cell containing only a def. Defining a function is like writing down a recipe; calling it is cooking.

def greet():
    print("Hello!")

print("Defined, but not yet called.")
greet()
greet()
Defined, but not yet called. Hello! Hello!

Docstrings: the function's own documentation

A docstring is a string literal written as the first line of a function body. It documents what the function does. Python stores it, and help(name) displays it — this is exactly what you read when you call help(len) or view a library's API.

def to_fahrenheit(celsius):
    """Convert a Celsius temperature to Fahrenheit."""
    return celsius * 9 / 5 + 32

help(to_fahrenheit)
Help on function to_fahrenheit in module __main__: to_fahrenheit(celsius) Convert a Celsius temperature to Fahrenheit.

Write docstrings in the imperative mood (“Convert…”, “Return…”), and describe what goes in and what comes out. Every function in this module's project has one.

Returning is not printing

This is the single most common beginner confusion about functions, so read both columns carefully. print() displays text for a human. return hands a value back to the program so it can be stored, calculated with, or displayed later.

Prints, returns nothing

def double_print(n):
    print(n * 2)

result = double_print(5)
print(result)
print(result + 1)
10 None TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

Returns a usable value

def double(n):
    return n * 2

result = double(5)
print(result)
print(result + 1)
10 11

A function that never executes a return statement returns None — Python's “no value here” object, introduced in Module 01. None displays as None and cannot be used in arithmetic. When a function seems to “lose” its answer, check whether you printed instead of returned.

return stops the function immediately

Code after a return in the same block never runs:

def bad_average(a, b):
    return a
    return b        # unreachable: never runs

That is a feature, not a bug — it lets you exit early on a special case:

def safe_divide(a, b):
    if b == 0:
        return 0.0   # leaves the function right here
    return a / b

A function may contain many return statements. Exactly one of them runs per call: the first one reached.

  Part 2 · Feed values into functions
  
Parameters and arguments


  
These two words are constantly mixed up, and the distinction makes error messages readable:


  
    
    
  • A parameter is a name in the definition: the blank to be filled.
    • 
    
  • An argument is a value in the call: what fills the blank.
    • 
  


  
def area(width, height):     # width and height are parameters
    return width * height

area(3, 2)                   # 3 and 2 are arguments


  
Python matches them by position by default. The first argument fills the first parameter,
  and so on. These are positional arguments. Order therefore matters:
  area(3, 2) and area(2, 3) both give 6, but
  power(2, 10) and power(10, 2) would not.


  
Keyword arguments name their target

  
A keyword argument uses parameter=value in the call. It says which
  parameter it fills, so order no longer matters and the call documents itself:


  
area(width=3, height=2)
area(height=2, width=3)     # identical result
area(3, height=2)           # positional first, then keyword


  
One firm rule: every positional argument must come before every keyword argument.
  area(width=3, 2) is a SyntaxError. You will see keyword arguments
  everywhere in ML libraries, precisely because a call such as
  train_test_split(X, y, test_size=0.2, random_state=0) would be unreadable with
  four bare positional values.


  
Default values make a parameter optional

  
A default value is written in the definition with =. If the caller
  omits that argument, the default is used:


  
def greet(name, greeting="Hello", punctuation="!"):
    return f"{greeting}, {name}{punctuation}"

print(greet("Maya"))
print(greet("Maya", "Welcome"))
print(greet("Maya", punctuation="?"))

  
Hello, Maya!
Welcome, Maya!
Hello, Maya?


  
Parameters with defaults must be listed after parameters without them —
  def f(a=1, b) is a SyntaxError. The third call above shows why
  keyword arguments matter: it skips greeting and sets only
  punctuation, which positional arguments cannot do.

Returning several values at once


  
A return statement may list several values separated by commas. Python packs
  them into one tuple and the caller can unpack them into separate names:


  
def split_time(total_minutes):
    """Return whole hours and remaining minutes."""
    hours = total_minutes // 60
    minutes = total_minutes % 60
    return hours, minutes

h, m = split_time(137)
print(f"{h} h {m} min")

both = split_time(137)
print(both)

  
2 h 17 min
(2, 17)


  
Unpacking requires the counts to match: a, b, c = split_time(137) raises
  ValueError: not enough values to unpack. This pattern is everywhere in ML code —
  X_train, X_test, y_train, y_test = train_test_split(...) is exactly this idea with
  four values.


  
Type hints: optional labels that document intent

  
Type hints annotate what a function expects and returns. Python does not enforce
  them at runtime; they exist for human readers and tools. You will see them in modern library
  code, so learn to read them now:


  
def to_fahrenheit(celsius: float) -> float:
    """Convert a Celsius temperature to Fahrenheit."""
    return celsius * 9 / 5 + 32


  
Read it as “celsius should be a float, and the function gives back a float”.
  Passing a string still runs and still fails the same way it would without the hint. This course
  writes hints only where they clarify.

  Part 3 · Know where a name lives
  
Scope: where a name is visible


  
A name's scope is the region of a program where that name can be used. Python has
  two scopes you need now:


  
    
    
  • Local scope — names created inside a function call. They exist only while that
    call runs, in that call's frame, and disappear when it returns.
    • 
    
  • Global scope — names created at the top level of a file or notebook. They exist
    for the whole program run.
    • 
  


  
def compute():
    inside = 10          # local to this call
    return inside * 2

outside = compute()
print(outside)
print(inside)            # NameError: name 'inside' is not defined


  
This is a feature. Because locals are private, two functions can both use a parameter called
  value without interfering, and you can read a function in isolation knowing its
  names cannot be silently altered from elsewhere.


  
Reading a global is allowed; rebinding one is not

  
A function may read a global name it does not define locally. But an assignment
  anywhere inside a function makes that name local for the entire call:


  

    

      
Reading works

      
tax_rate = 0.05

def with_tax(price):
    return price * (1 + tax_rate)

print(with_tax(100))

      
105.0

count = 0

  read on the right of = looks for a local that has no value yet. The

Shadowing: a local name hiding a global one

  
Shadowing happens when a local name has the same spelling as a global name. Inside
  the function, the local wins; outside, the global is untouched. Python looks names up in a fixed
  order — Local, then Enclosing function, then
  Global, then Built-in — commonly abbreviated
  LEGB.

Do not shadow a built-in name

    
Assigning to list, sum, max, dict,
    str, or type replaces the built-in for the rest of the session:

    
sum = 10          # sum is now an int, not a function
print(sum([1, 2]))  # TypeError: 'int' object is not callable

    
In a notebook the only cure is restarting the kernel or deleting the name. Use
    total, values, or scores instead. The B in LEGB is last
    for a reason: anything you define wins over the built-in.

  


  
Pure functions and side effects

  
A pure function depends only on its arguments and only affects the world through
  its return value. Anything else it does — printing, writing a file, changing a global, modifying
  a caller's list — is a side effect.


  
Prefer pure functions where you can: they are easy to test, easy to reason about, and safe to
  reuse. Keep the side effects (printing a report, saving a file) in a thin outer layer. The
  project in Part 8 is built exactly this way: pure calculation functions plus one function that
  prints.

Lists and sequences


  
Until now each variable held one value. A collection (or container) is
  a value that holds other values. The most used one is the list: an ordered,
  changeable collection written in square brackets.


  
scores = [90, 85, 77, 92]
names = ["ada", "turing", "hopper"]
mixed = [1, "two", 3.0, True]     # legal, but usually a design smell
empty = []

print(len(scores))
print(scores)

[90, 85, 77, 92]


  
The values inside are called elements or items. A list keeps them in
  the order you put them, allows duplicates, and can grow or shrink. In ML you will hold rows of
  data, feature names, and predictions in list-shaped values constantly.


  
Indexing: reading one element

  
An index is an element's position. Python counts from 0, so the
  first element is scores[0]. Negative indices count backwards from the end, so
  scores[-1] is the last element.

In-place methods return None

    
This is the most common list bug in beginner code:

    without assigning, or use the built-in sorted(), which leaves the
    original alone and returns a new list:

top_first = sorted(scores, reverse=True)

    
The same pattern applies to .reverse() versus reversed(), and to
    .append() — never write scores = scores.append(4).

  Part 6 · The idea that prevents strange bugs
  
Mutability, aliasing, and copies


  
This part separates people who use Python from people who fight it. It is
  short, and it is the highest-value section in the module.


  

    
The rule: a variable is a name attached to an object

    
Assignment never copies. b = a attaches a second name to the
    same object. Nothing is duplicated.

    
For immutable objects (int, float, str,
    bool, tuple, None) this is undetectable: you cannot
    change them in place, so any “change” builds a new object and moves one name to it.

    
For mutable objects (list, dict, set) it
    matters enormously: changing the object through one name is visible through every name.

  


  

    

      
Immutable: the names separate

      
a = 5
b = a
b = b + 1     # builds a NEW int

print(a, b)   # 5 6

    

    

      
Mutable: the names stay together

      
a = [1, 2, 3]
b = a
b.append(4)   # changes THIS list

print(a, b)   # [1, 2, 3, 4] [1, 2, 3, 4]

    

  


  
Two names for one object are called aliases, and the situation is
  aliasing. The difference between the two columns is not the assignment — it is whether
  the operation rebinds a name (b = b + 1) or mutates an object
  (b.append(4)).


  
is versus ==

  
a == b asks “do these have equal contents?”. a is b asks “are these
  the same one object?”. id(x) returns an object's identity number, which lets you
  prove it:


  
a = [1, 2, 3]
b = a
c = [1, 2, 3]

print(a == b, a is b)      # True True   -- same object
print(a == c, a is c)      # True False  -- equal contents, different objects
print(id(a) == id(b))      # True


  
Use == for values. Reserve is for comparing with None:
  write if items is None, never if items == None.

Shallow copies stop one level down

  
The three usual ways to copy a list — a.copy(), a[:], and
  list(a) — all make a shallow copy: a new outer list holding the
  same inner objects. If the elements are themselves mutable, they are still shared:


  
import copy

grid = [[1, 2], [3, 4]]
shallow = grid.copy()
deep = copy.deepcopy(grid)

shallow[0].append(99)      # mutates an inner list that grid also sees
print(grid)                # [[1, 2, 99], [3, 4]]

deep[1].append(77)         # fully independent
print(grid)                # [[1, 2, 99], [3, 4]]


  
copy.deepcopy() recursively copies everything. Reach for it only when you truly
  have nested mutable data — it is slower, and for flat lists a shallow copy is enough. This exact
  distinction returns in Module 07, where slicing a NumPy array gives a view that shares
  memory rather than a copy.


  
Passing a mutable object to a function

  
Arguments are passed the same way: the parameter becomes another name for the caller's object.
  So a function can change the caller's list — which is sometimes what you want, and sometimes a
  nasty surprise:


  

    

      
Mutates the caller's list

      
def add_bonus(scores):
    scores.append(100)     # in place
    return scores

original = [90, 85]
add_bonus(original)
print(original)            # [90, 85, 100]

    

    

      
Leaves the caller's list alone

      
def with_bonus(scores):
    return scores + [100]  # new list

original = [90, 85]
new = with_bonus(original)
print(original)            # [90, 85]

    

    


  
Neither is wrong, but be deliberate, and say which one your function does in its docstring. A
  function that both mutates its argument and returns a value is the most confusing
  option — that is exactly why list.sort() returns None.


  

    
Never mutate a collection while looping over it

    
numbers = [1, 2, 3, 4]
for n in numbers:
    if n % 2 == 0:
        numbers.remove(n)     # skips elements unpredictably
print(numbers)                # [1, 3] here, but do not rely on it

    
The loop tracks positions while the list shifts underneath it. Two safe fixes: iterate over
    a copy (for n in numbers[:]), or — better — build a new list:
    numbers = [n for n in numbers if n % 2 != 0]. Changing a dict's set of keys during
    for key in d raises RuntimeError: dictionary changed size during
    iteration outright.

  


  

    Optional deep dive Hashing, why dict lookup is fast, and what “unhashable” means
    

      
Every value is an object with an identity. In CPython, id(x)
      is derived from its memory address. Small integers and short strings are often
      interned — reused from a cache — so a = 5; b = 5; a is b may print
      True. That is an implementation detail, never something to rely on. Compare
      values with ==.

      
Why a dict lookup does not scan. A dict is a hash table. A
      hash function maps each key to an integer (hash("ada")), and that
      integer selects a slot in an internal array. Finding a key means computing one hash and
      looking at one slot, so the cost is roughly constant no matter how many pairs the dict holds.
      Searching a list, by contrast, compares elements one by one until it finds a match.

      

        
Operationlist / tupledict / set

        
          
x in collectionGrows with lengthNear-constant

          
Read by index or keyConstant by indexNear-constant by key

          
Append or addConstant (amortised)Near-constant

          
Insert or delete at the frontGrows with lengthNot applicable

        
      

      
For a million-element collection, x in a_list can be tens of thousands of
      times slower than x in a_set. When a membership test lives inside a loop, that
      difference is the whole runtime — a habit worth forming before you meet real datasets.

      
Why keys must be immutable. A key's slot is chosen from its hash. If the
      key could mutate, its hash would change and the dict could never find it again. So Python
      requires keys to be hashable, and mutable built-ins deliberately are not:
      hash([1, 2]) raises TypeError: unhashable type: 'list'. A tuple of
      immutable values is hashable, which is why {(0, 0): "origin"} works and is the
      standard way to key data by a coordinate pair.

      
The mutable-default trap, explained. Default values are evaluated once,
      when the def statement runs, and stored on the function object. A default list
      is therefore a single shared object living as long as the function does — the same aliasing
      rule from this section, appearing in a place nobody expects.

Comprehensions: loops as expressions


  
An enormous share of real code does one of two things to a collection: transform
  every element, or keep some elements. A comprehension is compact syntax for
  exactly that, and it is everywhere in ML code.


  

    

      
The loop you already know

      
squares = []
for n in range(1, 6):
    squares.append(n ** 2)

    

    

      
The same thing, as one expression

      
squares = [n ** 2 for n in range(1, 6)]

    

  


  

    
[n ** 2 for n in range(1, 6) if n % 2 == 0]

    

      
The square brackets say “build a new list”.

      
n ** 2 is the output expression:
      what to put in the new list for each kept element.

      
for n in range(1, 6) is the source, exactly as in a normal loop.

      
if n % 2 == 0 is the optional filter: elements failing it are
      skipped entirely. Result: [4, 16].

      
Read it in execution order — “for each n in the range, if it is even, put
      n ** 2 in the list” — not left to right.

    

  


  
The same syntax builds the other containers, by changing the brackets:


  
names = ["ada", "turing", "hopper"]

lengths      = [len(n) for n in names]              # list
lengths_set  = {len(n) for n in names}              # set  -- duplicates dropped
by_name      = {n: len(n) for n in names}           # dict -- key: value
long_names   = [n for n in names if len(n) > 3]     # filtered list
upper_names  = [n.upper() for n in names]           # transformed

print(lengths, lengths_set, by_name, long_names, upper_names, sep="\n")

  
[3, 6, 6]
{3, 6}
{'ada': 3, 'turing': 6, 'hopper': 6}
['turing', 'hopper']
['ADA', 'TURING', 'HOPPER']


  
A dict comprehension needs the key: value pair before
  for. A set comprehension looks identical to a list comprehension but with
  braces — and, being a set, discards duplicates. All three are single expressions, so they can be
  returned directly from a function, as the project's build_report does.

When not to use a comprehension

    
Comprehensions are for building a collection from another. Do not use one when:

    
You need side effects.
    [print(n) for n in names] builds a throwaway list of None values.
    Write a normal for loop.

    The logic needs more than one filter and one transform. Nested
    if/else chains inside a comprehension are far harder to read than the
    loop.

    It no longer fits on one readable line. Clarity beats compactness; a loop is
    not a lesser tool.

    
Nested comprehensions are legal —
    [value for row in grid for value in row] flattens a nested list, with the loops in
    the same order you would write them normally — but two levels is the sensible limit.

  


  
Generator expressions: the same syntax without the list

  
Round brackets produce a generator expression: it computes values one at a time
  instead of building a whole collection in memory. When a function consumes the values
  immediately, you can drop the brackets entirely:


  
print(sum(n ** 2 for n in range(1, 6)))       # 55, no list built
print(any(score < 50 for score in [90, 40]))  # True
print(max(len(n) for n in names))             # 6


  
Use one when you only need to pass values straight into sum(),
  any(), all(), min(), or max(). Keep a list

def average_minutes(minutes):
    """Return the mean daily minutes, or 0.0 for an empty list."""
    if not minutes:
        return 0.0
    return sum(minutes) / len(minutes)


def classify(average):
    """Return 'strong', 'building', or 'start small' for an average."""
    if average >= 45:
        return "strong"
    if average >= 20:
        return "building"
    return "start small"


def days_at_goal(minutes, goal=30):
    """Return how many days met or exceeded the goal."""
    return len([m for m in minutes if m >= goal])


def summarize(minutes, goal=30):
    """Return one learner's figures as a dict."""
    average = average_minutes(minutes)
    return {
        "days": len(minutes),
        "total": sum(minutes),
        "average": average,
        "habit": classify(average),
        "at_goal": days_at_goal(minutes, goal),
    }


def build_report(log, goal=30):
    """Return {name: summary} for every learner in the log."""
    return {name: summarize(minutes, goal) for name, minutes in log.items()}


def top_learner(report):
    """Return (name, total_minutes) for the learner with the most minutes."""
    best_name = max(report, key=lambda name: report[name]["total"])
    return best_name, report[best_name]["total"]


def print_report(report):
    """Display the report. The only function here with a side effect."""
    print("STUDY LOG REPORT")
    print("=" * 46)
    ranked = sorted(report, key=lambda name: report[name]["total"], reverse=True)
    for name in ranked:
        s = report[name]
        print(f"{name:<8}{s['days']:>3} days  {s['total']:>4} min  "
              f"avg {s['average']:>5.1f}  {s['habit']}")
    print("-" * 46)
    best_name, best_total = top_learner(report)
    print(f"Top learner: {best_name} with {best_total} minutes")
    total_all = sum(s["total"] for s in report.values())
    print(f"Class total: {total_all} minutes across {len(report)} learners")


study_log = {
    "maya": [30, 45, 20, 60],
    "sam": [60, 60],
