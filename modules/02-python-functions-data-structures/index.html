Functions: named, reusable computation

A function is a block of code with a name, inputs (parameters), and usually an output (return value). Two moments matter: definition (Python just memorizes the recipe — nothing runs) and call (Python jumps into the function with the given arguments, runs it, and comes back with the returned value).

def area(w, h):          # definition: nothing runs yet
    return w * h

room = area(3, 2)        # call: w gets 3, h gets 2, comes back with 6

The four core containers

  

    
When to use which

    

    list — ordered, changeable: scores = [90, 85, 77]. Your default.

    tuple — ordered, frozen: point = (3, 1). For fixed-shape records.

    dict — key → value lookup: ages = {"ada": 36, "alan": 41}. For "look up Y by X".

    set — unordered, no duplicates: tags = {"ml", "python"}. For membership tests.

The big one: names point at objects

  
This is the concept that separates people who use Python from people
  who fight it. Assignment never copies — it makes another
  name point at the same object. For immutable values (ints, strings,
  tuples) you can't tell the difference. For mutable ones (lists, dicts),
  changing the object through one name is visible through every name.

    Math deep dive Names vs. objects, id(), and why dicts are fast
    

      
Every value in Python is an object with an identity. id(x)
      returns it (in CPython, its memory address). a is b asks "same object?"
      while a == b asks "equal contents?" — the aliasing demo above is exactly the
      case where a is b is True, and after .copy() it's
      False while a == b would still start out True.

      
Shallow vs. deep copy: a.copy() copies the list but not
      the objects inside it. A list of lists copied shallowly still shares the inner
      lists — copy.deepcopy() is the recursive version. This exact issue reappears
      when you slice NumPy arrays (views!) in Module 07.

      
Why dict lookup is O(1): a dict is a hash table. The key is run through
      a hash function that maps it (near-)uniformly to a slot index in an internal array, so
      looking up a key costs roughly constant time regardless of dict size — versus scanning a
      list, which costs time proportional to its length. This is also why dict keys must be
      immutable (hashable): if a key could mutate, its hash would change and the dict could
      never find it again — the same reason a set can hold tuples but not lists.

    

  


  
Comprehensions: loops as expressions

  
Python has a compact syntax for the extremely common pattern "build a new list
  by transforming/filtering another." You'll see it constantly in ML code:

  
squares = [n ** 2 for n in range(1, 6)]          # [1, 4, 9, 16, 25]
evens   = [n for n in range(10) if n % 2 == 0]    # [0, 2, 4, 6, 8]

  
Read it inside-out: "for each n in the range (keeping only those
  passing the if), put n ** 2 in the new list." If a
  comprehension needs more than one transform and one filter, use a normal loop —
  clarity beats compactness.


  
Worked example

  
Count word frequencies — the "hello world" of dicts, and the ancestor of the
  token counting you'll meet in the LLM modules:

  
words = ["the", "cat", "sat", "on", "the", "mat", "the", "end"]

counts = {}
for w in words:
    if w in counts:
        counts[w] = counts[w] + 1
    else:
        counts[w] = 1

print(counts)   # {'the': 3, 'cat': 1, 'sat': 1, 'on': 1, 'mat': 1, 'end': 1}

  
Trace the first three iterations by hand: "the" isn't in the empty
  dict, so it's added with count 1; "cat" likewise; when "the"
  arrives again, the if branch runs and bumps it to 2.


  

    
Common pitfalls

    
Mutable default arguments — def f(items=[]) creates
    one list shared by every call that omits the argument. Use
    def f(items=None) and create the list inside.

    Forgetting return — a function without one returns
    None; printing inside a function is not the same as returning from it.

    Modifying a list while looping over it — skips elements unpredictably.
    Loop over a copy (for x in items[:]) or build a new list instead.
